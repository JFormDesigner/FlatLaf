# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

FlatLaf is a cross-platform Look and Feel for Java Swing. Library code must stay
compatible with **Java 8** (source/target 1.8), while also running on the latest
Java versions.

## Build commands

Gradle (Kotlin DSL) with wrapper; use `gradlew.bat` on Windows. Gradle itself
needs a recent JDK (CI uses 21); the code is compiled via toolchains.

- Build everything (compile, tests, sigtest check): `./gradlew build`
- Build/test against a specific Java toolchain (default is 8):
  `./gradlew build -Dtoolchain=17`
- Test one module: `./gradlew :flatlaf-core:test`
- Run a single test class / method:
  `./gradlew :flatlaf-core:test --tests com.formdev.flatlaf.ui.TestFlatStyling`
  `./gradlew :flatlaf-core:test --tests "com.formdev.flatlaf.ui.TestFlatStyling.<method>"`
- Static analysis (Error Prone, `-Werror`): `./gradlew errorprone`
- Public API signature check: `./gradlew :flatlaf-core:sigtestCheck` (part of
  `check`). After an intentional public API change in `com.formdev.flatlaf`,
  `com.formdev.flatlaf.themes` or `com.formdev.flatlaf.util`, regenerate
  `flatlaf-core/flatlaf-core-sigtest.txt` with `./gradlew :flatlaf-core:sigtestGenerate`.
- Skip publishing font JARs (e.g. when publishing FlatLaf): add `-PskipFonts`.
  Font JARs are still built because demo and other projects depend on them.

Tests use JUnit 5 and exist mainly in `flatlaf-core/src/test` (plus a few in
other modules).

## Modules

- `flatlaf-core` — the LaF itself (artifact `flatlaf`). Everything else depends on it.
- `flatlaf-extras` — SVG icons (`FlatSVGIcon`), UI inspectors, tri-state checkbox, etc.
- `flatlaf-intellij-themes` — bundled 3rd-party IntelliJ `.theme.json` themes with
  one generated Java class each. The classes and `FlatAllIJThemes` are generated by
  `flatlaf-demo/.../intellijthemes/IJThemesClassGenerator.java` from
  `flatlaf-demo/src/main/resources/.../intellijthemes/themes.json`.
- `flatlaf-swingx`, `flatlaf-jide-oss` — UI delegates for SwingX / JIDE components.
- `flatlaf-fonts/*` — font JARs (Inter, JetBrains Mono, Roboto, Roboto Mono).
- `flatlaf-natives/*` — C++ JNI libraries (Windows, macOS, Linux) built with Gradle's
  `cpp-library` via the `build-natives` task; the built binaries are **copied into
  `flatlaf-core/src/main/resources/com/formdev/flatlaf/natives`** and committed.
  `flatlaf-natives-jna` is development-only.
- `flatlaf-demo` — demo app; `flatlaf-theme-editor` — editor for theme `.properties` files.
- `flatlaf-testing` — many small manual Swing test apps (not unit tests), plus dump
  tools whose outputs live in `flatlaf-testing/dumps/` (e.g. `uidefaults/` produced
  by `UIDefaultsDump`). Those dumps are committed and diffed to review the effect of
  changes to theme properties/UI defaults.
- `buildSrc` — shared convention plugins: `flatlaf-toolchain`, `flatlaf-java9`,
  `flatlaf-module-info`, `flatlaf-publish`, `flatlaf-cpp-library`, `flatlaf-jni-headers`,
  `flatlaf-sigtest`.

## Architecture (flatlaf-core)

- **Multi-release JAR**: `src/main/java` is Java 8; `src/main/java9` contains
  Java 9+ overrides of some classes (compiled to `META-INF/versions/9`), and
  `src/main/module-info` holds `module-info.java` (compiled separately). When
  changing a class that has a java9 counterpart, update both.
- **Theme definition via properties files**, not Java code. `FlatLaf.properties`
  (loaded for all themes) plus per-theme files (`FlatLightLaf.properties`,
  `FlatDarkLaf.properties`, `FlatIntelliJLaf.properties`, `FlatDarculaLaf.properties`)
  in `src/main/resources/com/formdev/flatlaf/`. `UIDefaultsLoader` parses them:
  variables (`@var`, `$key` references), color functions (`lighten()`, `darken()`, …),
  platform/LaF prefixes like `[win]`, `[mac]`, `[linux]`, `[light]`, `[dark]`, and
  `[style].xyz` style classes. Addons contribute properties via `FlatDefaultsAddon`
  (ServiceLoader). IntelliJ `.theme.json` themes are mapped onto these defaults by
  `IntelliJTheme` (with extra mappings in `IntelliJTheme$ThemeLaf.properties`).
- `FlatLaf` is the abstract base LaF; concrete themes (`FlatLightLaf`, …) are thin
  subclasses. `FlatPropertiesLaf` loads a theme from a user properties file.
- **UI delegates** in `com.formdev.flatlaf.ui` (`Flat*UI`, `Flat*Border`) read their
  values from UI defaults in `installDefaults()`. Fields that are UI-default-driven
  are documented with `@uiDefault` javadoc tags; client properties with
  `@clientProperty` (constants in `FlatClientProperties`).
- **Per-component styling**: most delegates support the `FlatLaf.style` /
  `FlatLaf.styleClass` client properties through `FlatStylingSupport`
  (`@Styleable` fields, `applyStyle`, `getStyleableInfos`). Adding a new UI default to
  a delegate usually also means making it styleable and updating the styling tests
  (`TestFlatStyling`, `TestFlatStyleableInfo`, `TestFlatStyleableValue`) and
  `flatlaf-testing/dumps/styleable-infos.txt`.
- HiDPI scaling goes through `com.formdev.flatlaf.util.UIScale` (`scale()` for sizes);
  painting helpers are in `FlatUIUtils`.
- Native window decorations / OS integration: `FlatNativeLibrary`,
  `FlatNativeWindowsLibrary`, `FlatWindowsNativeWindowBorder`, etc. (JNI headers are
  generated from `compileJava` into `build/generated/jni-headers`).

## Code style

- Source files are **UTF-8** encoded (without BOM), **tab** indentation, LF line
  endings (see `.editorconfig`).
- Spaces inside parentheses of method calls/declarations and control statements:
  `if( x != null )`, `foo( a, b )`, `void bar( int x ) {`. No space before `(`.
- Every source file starts with the Apache 2.0 license header
  (`Copyright <year> FormDev Software`).
- User-visible changes are recorded in `CHANGELOG.md`.
